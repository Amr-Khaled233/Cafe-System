# نظام إدارة كافيه

طاولات · طلبات · شيفتات · **مخزون بالوصفات وخصم تلقائي** · جرد · تقارير.
عربي (RTL) وإنجليزي (LTR) بالكامل. الصلاحيات متطبّقة في السيرفر.

## 1) التشغيل المحلي

### المتطلبات
- Node.js 18 أو أحدث
- MongoDB — **يفضّل replica set** عشان الـ transactions تشتغل (تفاصيل تحت)

### الخطوات

```bash
npm install
cp .env.example .env      # وبعدين املا MONGO_URI و JWT_SECRET
npm run seed:reset        # بيانات تجريبية كاملة
npm run dev               # الـ API على 4100 والواجهة على 5174
```

افتح **http://localhost:5174**

| الحساب | المستخدم | الباسورد |
|---|---|---|
| مدير | `manager` | `manager123` |
| ريسبشن | `reception` | `reception123` |
| ريسبشن ٢ | `reception2` | `reception123` |

> البورتات 4100 و 5174 مش الافتراضية المعتادة — اتغيّرت لأن 4000 و 5173 مشغولين
> بمشاريع تانية على الجهاز. غيّرهم من `.env` و `vite.config.js` لو عايز.

### مونجو محلي بالـ Docker (مع transactions)

الـ transactions محتاجة replica set. `mongod` العادي مش هيديك ده:

```bash
docker run -d --name cafe-mongo -p 27018:27018 mongo:7 \
  --replSet rs0 --bind_ip_all --port 27018

docker exec cafe-mongo mongosh --port 27018 --quiet \
  --eval "rs.initiate({_id:'rs0',members:[{_id:0,host:'localhost:27018'}]})"
```

وبعدين في `.env`:

```
MONGO_URI=mongodb://localhost:27018/cafe?replicaSet=rs0
```

اتأكد إنها شغالة: `curl http://localhost:4100/api/health` لازم يرجّع `"transactions":true`.

> لو شغّلت على `mongod` عادي، النظام **هيشتغل عادي** بس من غير transactions —
> السيرفر بيطبع تحذير عند الإقلاع. للتطوير ده تمام، للإنتاج لأ.

## 2) النشر على Vercel

الواجهة بتتبني static، والـ API بيشتغل serverless من `api/index.js`.

### قاعدة البيانات من جوّه Vercel

**MongoDB Atlas متاح في Vercel Marketplace** — بتتعمل من الداشبورد نفسه من غير حساب منفصل:

1. افتح مشروعك على Vercel → تبويب **Storage**
2. **Connect Database** → **Marketplace** → اختار **MongoDB Atlas**
3. اختار الخطة (فيه Free tier) والمنطقة، واربطها بالمشروع
4. Vercel بيحقن الـ connection string في متغيّرات البيئة **أوتوماتيك**

الكود بيقرا `MONGO_URI` أو `MONGODB_URI` أو `DATABASE_URL` — أي اسم من دول
بيشتغل، فبعد الربط **مش محتاج تكتب متغيّر قاعدة بيانات بإيدك**.

> ميزة إضافية: أطلس دايماً replica set، يعني الـ transactions شغالة من أول لحظة —
> وده اللي بيخلّي الخصم من المخزون وتعديل الفاتورة عملية واحدة ماتتجزّأش.

### متغيّرات البيئة المطلوبة

في **Settings → Environment Variables** ضيف:

| المتغيّر | القيمة | إجباري |
|---|---|:---:|
| `JWT_SECRET` | نص عشوائي 32 حرف على الأقل — **إجباري** | ✅ |
| `SMTP_USER` / `SMTP_PASS` | جيميل + App Password — لازمين لـ«نسيت الباسورد» | ➖ |
| `APP_URL` | رابط موقعك — بيتحط في إيميل إعادة التعيين | ➖ |
| `NODE_ENV` | Vercel بيظبطه `production` لوحده — **ماتضفهوش** | ➖ |
| `TZ_NAME` | `Africa/Cairo` | ➖ |
| `JWT_HOURS` | `12` | ➖ |
| `BLOCK_WHEN_OUT_OF_STOCK` | `false` | ➖ |
| `VITE_CURRENCY` | `EGP` — لازم يتظبط **قبل** البناء لأنه بيتحقن في الواجهة | ➖ |
| `MONGO_URI` | **مش محتاجه** لو ربطت Atlas من Marketplace | ➖ |

لتوليد `JWT_SECRET`:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

### النشر

```bash
npm i -g vercel
vercel            # معاينة
vercel --prod     # إنتاج
```

`NODE_ENV=production` بيخلّي الكوكي `secure` — يعني HTTPS بس، وده اللي Vercel بيديه.

### أول تشغيل بعد النشر

القاعدة الجديدة فاضية. شغّل الـ seed عليها من جهازك:

```bash
MONGO_URI="<الرابط من Vercel>" npm run seed:reset
```

الرابط بتلاقيه في Vercel → Storage → قاعدة البيانات → `.env.local` / Connect.

> ⚠️ `seed:reset` **بيمسح كل البيانات**. على قاعدة فيها شغل حقيقي استخدم `npm run seed` بس.

## 4) المزايا

### الطاولات
جدول بسيط: رقم · حالة · إجمالي · مدة الجلسة. المدير بيتحكم في العدد من زرار
واحد («عدد الطاولات») — بيزوّد الناقص ويعطّل الزيادة، والطاولة اللي عليها
فاتورة مفتوحة مابتتعطّلش.

**دمج الطاولات:** الكاشير يقدر يضم أكتر من طاولة على فاتورة واحدة والحساب
يبقى عليهم سوا. لو الطاولة عليها فاتورة مفتوحة، أصنافها بتتنقل للفاتورة
الأساسية وفاتورتها بتتقفل كـ `merged` — ومستبعدة من التقارير عشان نفس
البيع مايتعدّش مرتين. وفيه فك دمج برضه.

### أنواع الأصناف (سادة / مظبوط / زيادة)
الصنف ممكن يكون ليه أنواع، وكل نوع بوصفته الكاملة — فالقهوة السادة مابتخصمش
سكر خالص، والزيادة بتخصم 20 جم. الصنف اللي ليه أنواع **لازم** تحدد نوعه وقت
الطلب (`VARIANT_REQUIRED`)، والنوع بيتسجّل في الفاتورة زي السعر بالظبط.
كل نوع ليه سعره (فرق سعر اختياري) ومتاحه محسوب من الرصيد.

### المكاييل (معلقة بدل جرام)
كل خامة ممكن تتعرّف عليها مكاييل: **معلقة = 5 جم**، **كوب = 200 مل**،
**جرعة = 18 جم**. في الوصفة بتكتب «معلقتين» والنظام بيحوّلها لوحده.
التخزين والحسابات كلها بتفضل بوحدة الأساس، فالجرد والتكلفة مابيتأثروش.
وشاشة الخامة بتقولك المعلقة بتكلّف كام.

### العمّال والشيفت
العمّال (باريستا/مطبخ/ويتر) بيتسجّلوا عند المدير — **مالهمش حساب دخول**.
لما الريسبشن يفتح شيفت بيحدد مين موجود، ويقدر يعدّلهم في أي وقت.
الأسماء بتتنسخ في الشيفت، فلو العامل اتشال بعدين الشيفتات القديمة تفضل مفهومة.

### اليومية
كل يوم بشيفتاته: مواعيد الشيفت · الكاشير · العمّال · الإيراد · تقسيم الدفع ·
فرق الكاش. وعلى مستوى اليوم: تكلفة الخامات · اللي اتسلّم · الهالك ·
المصروفات · **صافي الربح**.

### نسيت الباسورد (بالإيميل)

الموظف بيضغط «نسيت الباسورد؟» في شاشة الدخول، بيكتب إيميله أو اسم المستخدم،
وبيوصله رابط على إيميله يحط بيه باسورد جديد.

- الرابط **بيشتغل مرة واحدة** وصلاحيته 30 دقيقة (`RESET_TTL_MINUTES`)
- بنخزّن **هاش التوكن بس** — الأصل بيتبعت في الإيميل ومابيتخزّنش في القاعدة
- تغيير الباسورد **بيقفل كل الجلسات المفتوحة** للحساب ده على كل الأجهزة
- 6 محاولات كل 15 دقيقة لكل IP

#### إعداد جيميل

جيميل مابيقبلش باسورد حسابك العادي. لازم **App Password**:

1. فعّل **التحقق بخطوتين**: [myaccount.google.com/security](https://myaccount.google.com/security)
2. ولّد باسورد تطبيق: [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords)
3. حط الـ 16 حرف (من غير مسافات) في `SMTP_PASS`

```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_USER=your.cafe@gmail.com
SMTP_PASS=abcdefghijklmnop
SMTP_FROM="نظام الكافيه <your.cafe@gmail.com>"
APP_URL=https://your-project.vercel.app
```

`APP_URL` مهم — منه بيتبني الرابط اللي في الإيميل.
لو الإيميل مش متظبط، الشاشة بتقول كده بوضوح بدل ما تفضل مستنية رسالة مش جاية.

### تحكّم المدير في الحسابات

من شاشة **الموظفين**:

| الإجراء | بيعمل إيه |
|---|---|
| إضافة/تعديل حساب | الاسم · اليوزر · **الإيميل** · الدور · الحالة |
| تغيير الباسورد | بيغيّره **وبيقفل كل جلساته** فوراً |
| **رابط باسورد** | بيبعت للموظف رابط يغيّر بيه بنفسه — أنضف من إن المدير يعرف باسورد حد |
| **إنهاء الجلسات** | بيسجّل خروجه من كل الأجهزة على طول من غير ما يستنى التوكن يخلص |
| إيقاف الحساب | مايدخلش تاني، وجلسته المفتوحة بتموت |

آخر دخول لكل موظف ظاهر في الجدول، وكل العمليات دي بتتسجّل في **سجل العمليات**.

> آخر مدير نشط مايتعطّلش ومايتحوّلش لريسبشن — عشان مايحصلش قفل على النظام.

### المصروفات
إيجار · مرتبات · كهرباء · مستلزمات · صيانة · تسويق · مواصلات · أخرى.
بتتسجّل بتاريخها، والشاشة بتقولك **بتصرف في إيه أكتر حاجة** بنسبة كل بند،
وتصدير CSV لآخر الشهر.

```
صافي الربح = الإيراد − تكلفة الخامات − المصروفات
```

## 5) الأفكار اللي النظام مبني عليها

### الرصيد مايتعدّلش مباشرة أبداً

مفيش أي راوت بيكتب في `Ingredient.currentQty`. أي تغيير بيعدّي من `applyMovement`
في [`server/inventory.js`](server/inventory.js) اللي بيعمل حاجتين مع بعض:
بيزوّد/يقلّل الرصيد، وبيسجّل `StockMovement` فيه `balanceAfter`.

يعني أي رصيد في أي لحظة تقدر تفسّره وتعيد بناءه من السجل — وده اللي بيخلّي
الجرد يشتغل صح.

`PATCH /api/ingredients/:id` بيرفض `currentQty` بكود `USE_MOVEMENT_INSTEAD`.

### الخصم وقت الإضافة، مش وقت الدفع

المشروب بيتعمل لما الصنف يتضاف للفاتورة، فالخصم بيحصل ساعتها:

| العملية | الحركة |
|---|---|
| إضافة صنف | خصم كل خامة في وصفته × الكمية (`sale`) |
| زيادة/نقصان الكمية | خصم أو رد **الفرق بس** |
| حذف الصنف | رد الكمية (`return`) |
| إلغاء الفاتورة | رد كل خامات كل الأصناف (`return`) |

### الرد بيطلع مطابق للخصم دايماً

كل سطر في الفاتورة بيخزّن `appliedRecipe` — نسخة الوصفة **وقت الخصم**.
الرد بيستخدم النسخة دي مش الوصفة الحالية، فلو المدير عدّل الوصفة بعد ما الصنف
اتضاف، الرد برضه بيرجّع نفس الكميات اللي اتخصمت بالظبط.

### الخصم مايتكررش

كل سطر عنده `stockApplied` و `appliedQty`. والواجهة بتبعت `clientRequestId`
مع كل إضافة — لو نفس الريكوست وصل مرتين، السيرفر بيرجّع الفاتورة زي ما هي
ومعاها `duplicate: true` من غير خصم تاني.

### الخامة اللي خلصت ماتوقفش الطلب

الزبون قاعد. لو الرصيد مش كفاية، الطلب بيعدّي والرصيد بينزل بالسالب —
عشان الجرد يبان فيه العجز الحقيقي — والواجهة بتنبّه.
لو عايز العكس، حط `BLOCK_WHEN_OUT_OF_STOCK=true` وساعتها بيترفض بكود
`OUT_OF_STOCK` مع أسماء الخامات الناقصة.

### الصلاحيات في السيرفر

الواجهة بتخفي الأزرار، **السيرفر هو اللي بيمنع**. راوترات الإحصائيات والمخزون
والوصفات والجرد والتقارير والموظفين والسجل كلها بتبدأ بـ `router.use(managerOnly)`.
أي نداء من ريسبشن بيرجع `403` قبل ما يوصل للـ handler.

وكمان: `buildOrderFilter` بيتجاهل أي `userId` أو `shiftId` أو فترة بيبعتهم
الريسبشن في الـ query ويقفله على شيفته هو.

### الأرقام القديمة ماتتغيّرش

- سعر الصنف متنسوخ جوّه سطر الفاتورة → تغيير المنيو مايأثرش على فاتورة قديمة
- `unitCost` متجمّد جوّه كل حركة مخزون → تغيير تكلفة الخامة مايغيّرش قيمة حركة قديمة
- الفاتورة المدفوعة ماتتمسحش — بتتعمل `void` مع سبب وبتفضل في `AuditLog`

## 7) الأمان

المراجعة الأمنية اتعملت على السيرفر الشغّال — **65 اختبار هجومي، كلهم ناجحين**.

### اللي اتحصّن

| الطبقة | الإجراء |
|---|---|
| **الباسوردات** | bcrypt بـ 10 rounds · `passwordHash` عليه `select: false` فمابيخرجش في أي رد |
| **الجلسة** | JWT في كوكي `HttpOnly` + `SameSite=Lax` + `Secure` في الإنتاج — الجافاسكربت مايقدرش يقراه، والـ CSRF مقفول |
| **خوارزمية التوكن** | مثبّتة على HS256 — يمنع هجوم `alg:none` وتبديل الخوارزمية |
| **مصدر الدور** | الدور بيتقرا من قاعدة البيانات كل ريكوست، **مش من التوكن** — توكن موقّع صح فيه `role: manager` مايديش صلاحيات |
| **الحساب المعطّل** | الجلسة المفتوحة بتموت فوراً لما المدير يعطّل الحساب |
| **كشف الحسابات** | نفس الرد ونفس الزمن للمستخدم الغلط والباسورد الغلط (مقارنة hash وهمي) |
| **حقن NoSQL** | كل مدخل بيتحوّل `String()` أو بيتحقق بـ `isValidObjectId` أو بقائمة بيضا — `{"$ne":null}` مابيعديش |
| **ReDoS** | رموز الـ regex في البحث بتتهرب قبل بناء الـ RegExp |
| **حقن صيغ CSV** | قيمة بتبدأ بـ `=` أو `+` أو `-` أو `@` بتتسبق بفاصلة عليا — يمنع تنفيذ معادلات عند فتح التقرير في إكسل |
| **التعديل الجماعي** | كل `PATCH` بياخد قائمة حقول محدّدة، مافيش `req.body` بيتمرّر كما هو |
| **هيدرات** | `nosniff` · `X-Frame-Options: DENY` · `Referrer-Policy` · `no-store` · إخفاء `X-Powered-By` |
| **حد المحاولات** | 20 محاولة دخول كل 10 دقايق لكل IP |
| **حجم الطلب** | 1MB، والأكبر بيرجّع `PAYLOAD_TOO_LARGE` |
| **السر** | السيرفر بيرفض يقوم أصلاً لو `JWT_SECRET` ناقص أو أقصر من 32 حرف أو لسه على قيمته الافتراضية في الإنتاج |

### اللي اتغطّى في الاختبار

المصادقة والجلسات · الوصول بدون توكن لـ 16 endpoint · تصعيد صلاحيات الريسبشن على
27 مسار قراءة و6 مسارات كتابة · تزوير الـ JWT بـ 5 طرق · الحساب المعطّل ·
IDOR وعزل الشيفتات · الحقن في الفلاتر · قواعد العمل (خصم >100%، كمية سالبة،
إلغاء مرتين، تزوير حركة بيع) · قواعد الحسابات · حقن CSV · الهيدرات ·
حدود الحمل · تسريب رسايل الأخطاء.

> ⚠️ قبل النشر: **غيّر `JWT_SECRET`** وغيّر باسوردات حسابات الـ seed.
> الـ `.env` مستبعد من git، وما اترفعش على المستودع.

## 8) ملاحظات

- **ألوان الرسوم** متحقّق منها لعمى الألوان في الوضعين (فاتح وغامق) — الترتيب ثابت
  فتغيير الفلتر مايعيدش تلوين الأصناف الباقية.
- **التوقيت**: كل التجميع بيحصل بتوقيت `TZ_NAME` (افتراضي القاهرة)، فـ«النهاردة»
  معناها اليوم في الكافيه مش في UTC.
- **تكلفة الخامات في لوحة الإحصائيات** محسوبة من حركات المخزون بتكلفتها المتجمّدة
  (تاريخية ودقيقة)، أما **تقرير المبيعات بالصنف** فبيحسبها من الوصفة والتكلفة
  الحالية (زي ما المواصفة طالبة) — فممكن يختلفوا لو التكاليف اتغيّرت خلال الفترة.
- **الـ rate limit** على تسجيل الدخول: 20 محاولة كل 10 دقايق لكل IP.
